# 설계 67 — 가로 점검 2차 기준(점검 전에 고정, 2026-11-14 초안)

가로 점검은 기계 검사가 아니다 — 모델이 코드를 읽고 결함 후보를 낸다(AI 판단). 이 문서는 그 판단을 ① 같은 기준으로 묶고 ② 실행으로 확인하고 ③ 점검자 자신의 놓침을 재는 장치를 미리 정한다. 점검 결과는 번들 84 의 입력이다.

## 1. 감시자를 감시하는 장치

| 장치 | 무엇을 막나 | 어떻게 |
|---|---|---|
| ① 재현 의무 | 그럴듯한 오탐 | 지적마다 입력·실행 명령·실제 출력. 점검자가 `target/classes` 에 scratch 탐침을 붙여 돌린 것만 받는다. 「아마」·「~일 수 있다」 는 버린다 |
| ② 판정자 분리 | 점검자의 착각·과장 | 받은 지적의 탐침을 실행 세션(Opus)이 다시 돌린다. 출력이 다르면 버린다 |
| ③ 과거 결함 보정 | 점검자가 얼마나 놓치나(거짓 음성) | 정답을 아는 옛 트리에서 같은 점검을 한 번 돌려 재현율을 잰다 — 3절 |
| ④ 이중 독립 점검(선택) | 남은 결함 어림 | 영역 하나에 서로 모르는 점검자 둘. 둘이 낸 수 n1·n2 와 겹친 수 m 으로 전체 어림 N ≈ n1·n2/m(포획-재포획). m = 0 이면 「어림 불가 — 더 남았다」 로 읽는다 |
| ⑤ 고친 뒤 기계 관문 | 다시 생김 | 남은 지적은 전부 실패하는 시험 먼저(RED) → 고침 → 시험·`verify.sh`·CI 가 매번 막는다. 이 단계부터는 판단이 아니라 기계다 |

한계 — ③④ 는 어림이다. 「점검 끝 = 결함 없음」 이 아니다. 재현율·어림은 compare 에 숫자로 남긴다.

## 4. 공통 점검표 — 모든 영역

각 질문은 「길이 있나」 를 묻는다. 있으면 그 길을 실제로 밟는 입력을 만든다.

**4.1 절대 규칙**
- 1 외부 통신: `127.0.0.1` 밖으로 나가는 소켓·URL·UNC·`file://` 원격·XML 외부 엔티티·DTD·스키마 내려받기 · 사용자 값이 경로가 되는 자리에서 `\\서버` 가 지나가나
- 2 비밀번호: H2·로그·응답·오류 글·결과 파일·백업에 비밀번호가 실리나 · `toString`·예외 글·Jackson 직렬화로 새나
- 3 코드 본문: 검사 이력·로그·오류 글·H2 에 사용자 코드·SQL 결과·값이 남나(예외 `getMessage` 를 그대로 싣는 자리)
- 6 외부 DB 읽기만: `ReadOnlyJdbc` 를 안 거치는 연결 · SELECT 로 위장한 쓰기(부작용 함수는 후보 ⑪ — 제외) · 메타 조회가 쓰기를 일으키나
- 7 원본 안 고침: 결과 폴더 밖 쓰기 · 원본 폴더 안 결과 폴더 · 덮어쓰기 확인 없이 기존 파일 지움

**4.2 입력 극단값** — 각 진입로(화면 API·CLI·프로필 YAML·읽는 파일)마다
- 빈 값·null·공백만 · 0개·1개·아주 많이(1만 표, 10만 줄) · 한 줄 10MB 근처 · 깊은 중첩(괄호·태그·제네릭 500 단)
- 인코딩 BOM·CRLF·혼합 줄끝·EUC-KR·잘못된 UTF-8 · 한글·공백·따옴표·`$`·`#` 든 이름 · 방언 예약어 이름 · 대소문자 섞인 이름
- 숫자 경계(0·음수·최대 정밀도·NUMBER 정밀도 없음) · 날짜(윤년·시간대) · 경로(긴 경로·`..`·심볼릭 링크·정션·드라이브 루트)

**4.3 출력 정확도** — 만든 것이 실제로 쓰이나
- SQL·DDL: 그 방언에서 문법이 맞나(따옴표·식별자·세미콜론·주석 안 글자) · 같은 입력을 두 번 넣어도 같은 결과인가(순서 안정)
- 자바·JSP·XML: 컴파일·파싱되나 · import·패키지·이름 충돌
- xlsx: 셀 형식(숫자가 글로)·병합·수식 인젝션(`=`·`+`·`-`·`@` 로 시작하는 값)·시트 이름 31자·금지 글자
- 골든이 못 보는 꼴: 골든 입력이 다루지 않는 분기를 하나라도 찾으면 그 입력으로 출력을 본다

**4.4 오류 경로**
- 예상 못 한 예외가 500 + 「서버 오류」 로 끝나나, 아니면 사용자에게 사유가 보이나(400 이어야 할 것이 500)
- 작업(JobManager)이 RUNNING 에 멈추나 · 취소가 듣나 · 실패 뒤 반쯤 쓴 결과 파일·임시 파일이 남나
- 부분 실패를 성공으로 보고하나(건수·「못 읽음」 이 0 으로 나가는 길)

**4.5 자원** — 스트림·`ResultSet`·`Connection`·`Process`·임시 파일·스레드를 닫나 · 예외 길에서도 닫나 · 같은 파일을 두 작업이 동시에 쓰나

**4.6 판정 중복** — 같은 판정(경로 검사·식별자 검사·비밀번호 가림·방언 키)이 여러 곳에 복사돼 서로 어긋나나(0-87 꼴)

**4.7 보정에서 드러난 범주(2026-11-14)** — 보정 점검자가 놓친 꼴을 자리 이름 없이 범주로 더한다
- ① GET·HEAD 요청도 부작용(프로세스 실행·파일 쓰기)을 일으키나 · 다른 사이트의 페이지가 그 요청을 일으킬 수 있나
- ② 모든 `Pattern`·`replaceAll`·`split`·`matches` 정규식에 20 만 자 입력과 교대 반복을 넣는다(스택 넘침·역추적)
- ③ 읽는 모든 파일·요청 본문의 크기 상한 — 큰 입력에서 OOM·413·멈춤
- ④ 쓰는 모든 API·명령의 쓰기 자리가 실행 폴더·결과 폴더 밖으로 나가나
- ⑤ 비밀·위험 판정(비밀번호 가림·경로 검사·SQL 종류)을 우회하는 입력 꼴 — 방언·문법(URL 꼴·YAML 꼴)마다
- ⑥ 예외와 `java.lang.Error` 의 글·스택이 로그·응답으로 가는 모든 길(프레임워크 기본 처리기 포함)
- ⑦ 시간 초과·취소 뒤 자식·손자 프로세스·스레드가 남나

## 5. 영역별 질문

**A 생성기**
- `DdlGen`·`AlterGen`: 다섯 방언 출력이 그 DB 에서 실행되나 — 예약어·대소문자 이름·DEFAULT 식·CHECK·COMMENT 안 따옴표·시퀀스·IDENTITY · 방언 한계(이름 길이·정밀도) 넘침 처리
- `DdlReader`: 붙여 넣은 DDL 의 주석·문자열 안 `;`·괄호 · 같은 표 두 번 · ALTER 순서 · 읽다 실패한 표를 조용히 버리나(후보 ⑥ 백슬래시는 제외)
- `InsertGen`: 값 이스케이프(따옴표·줄바꿈·NUL·유니코드) · NULL vs 빈 문자열 · 날짜·LOB · 행 수 많을 때
- `Generator`·`TemplateSet`·`Templates`: 생성 소스가 컴파일되나(egov35·egov4·spring 세트) · 표·컬럼 이름이 자바 예약어·숫자 시작·한글일 때 · 결과 폴더 밖 쓰기
- `DtoGenerator`·`TypeMapping`·`Validation`·`FieldRoles`: 타입 매핑 빈칸(모르는 네이티브 타입) · 검증 주석이 CHECK 와 어긋남

**B 산출물·보고**
- xlsx 기입(`report`): 양식 행 수 넘침 · 병합 셀에 쓰기 · 수식 인젝션 · 매핑 YAML 이 없는 시트·열을 가리킬 때
- `Definitions`·`Standards`·`Grades`·`Coverage`·`Relations`: 스냅샷이 비거나 표 하나일 때 · 같은 이름 다른 스키마 · 표준 사전 비었을 때
- `StructureLint`: 열다섯 규칙의 경계(FK 순환·자기 참조·복합 키) · 기준값 0·null
- `quality`: 방언 다섯 · 대소문자 섞인 이름은 후보(제외)
- `logical`: `Masking` 이 값이 아닌 것을 가리나·가려야 할 것을 놓치나 · `CommentDdl` 따옴표 · `DomainMatcher` 오탐

**C 프로그램 분석**
- `SqlTables`·`SqlJoins`: 표 추출 — 서브쿼리·CTE·`MERGE`·동적 SQL(`${}`)·주석 안 표 · 스키마 접두
- `JavaGraph`·`TypeBind`·`MapperIndex`·`JpaIndex`: 같은 이름 다른 모듈 · 상속·제네릭 · 못 푼 것이 「못 맞춤」 으로 보이나, 조용히 빠지나
- `Screens`·`JspLinks`·`Menus`·`CrudViews`: JSP include 순환 · 상대 경로 `..` · 메뉴 없는 화면
- `SqlProbe`: 감싼 SQL 이 원문 주석·세미콜론·`ORDER BY`·`FOR UPDATE` 로 깨지거나 다른 문장이 되나(부작용 함수는 후보 ⑪ — 제외)
- `vcs`: 저장소 설정 명령 실행(0-83c 이후 남은 길) · 이상한 파일 이름(줄바꿈·따옴표) · 큰 diff

**D 코드 검사**
- 규칙 147 가운데 양성·음성 단언이 없는 규칙 · 주석·문자열 안 오탐 · 억제 표식(`tb-ignore`) 범위가 넓거나 좁음
- `RegexRule` 줄 단위 맞춤의 경계(여러 줄 꼴) · `JavaRules`·`Taint` 의 같은 이름 지역 변수·람다·내부 클래스
- `CheckRunner`·`CheckStore`: 건수(「못 읽음」·「억제」·「파싱 실패」)가 실제와 맞나 · 변경분 모드(`--changed-only`)에서 지워진·이름 바뀐 파일
- 결과 저장에 코드 본문이 안 들어가나(절대 규칙 3 — `excerpt` 칸 확인)

**E 코드 정리**
- 고침마다: 고친 글이 컴파일되나 · 의미가 바뀌나 · 주석·문자열·텍스트 블록을 건드리나 · 두 고침이 같은 줄을 만질 때 순서
- `Edits`: 겹친 편집 · CRLF·BOM·인코딩 보존 · 마지막 줄 줄끝
- `StarImportFix`·`SwitchFix`·`InterruptFix`·`LogFix`·`PiiFix`·`SyntaxFix`: 각자 「건너뜀」 사유가 맞나, 고쳐야 할 것을 건너뛰나 · 번들 83 리뷰 C1 같은 「구문은 안 깨지는데 의미가 바뀌는」 고침

**F DB 경계**

- `fs`: 읽기·목록·쓰기 API 가 비밀(프로필)·결과 폴더 밖을 건드리나
- `job`: 작업 상태 전이(실패·취소·Error) · 동시 작업 상한

**G2 CLI·설정·글·화면**
- `cli`: 끝 코드가 실패를 0 으로 내는 길 · 화면 라우트와 결과가 다른 길 · 인자 없는 경우

## 6. 증거 기준 — 지적 하나의 꼴

```
- 영역 · 파일:줄
- 무엇이 틀렸나(한 문장)
- 재현: 입력(글 그대로 또는 만드는 코드) · 실행(탐침 클래스·명령) · 실제 출력 · 기대 출력
- 사용자가 겪는 것(한 문장) — 등급의 근거
```
