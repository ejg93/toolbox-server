## 3. 설계 결정 — 전부 [고정]

### 공통 — 지적 = 고침
1. 고침 다섯의 대상은 **지적 규칙의 Hit 노드**다. 수정기(`ValueFix`·`ResourceFix`)는 단계 안에서 글을 다시 파싱해 `ValueAst.apply(cu, 대상 규칙)`·`ResourceAst.apply(cu, {TRY_WITH_RESOURCES})` 를 부르고 그 노드의 `Range` 로만 글을 바꾼다. 지적 판정 코드를 복사하지 않는다. 그래서 「지적 없는 고침」 은 구조상 0 이고, 「지적은 있는데 고침 없음」 은 전부 `Skip(stage, "줄 n: 사유")` 로 남는다 — 사유는 §3-14·§3-24 의 목록 밖 글을 만들지 않는다.
2. 수정기는 **한 줄 안 노드만** 바꾼다(`begin.line == end.line`). 한 줄에 Hit 가 여럿이면 열 내림차순으로 한 글에 합쳐 `Edits.replace(line, 새 줄)` 한 번. 줄 삽입 없음. 줄 삭제는 라-3 만.
3. `Cleanup.javaUnsafe(text, cur)` 가 null 이 아니면 그 단계는 사유 하나로 건너뛴다(①·③ 과 같다).

### ResourceAst(5-60a) — 지적 둘
4. 상수 — `RESOURCE_LEAK = "security.resourceLeak"` · `TRY_WITH_RESOURCES = "java.tryWithResources"` · `EXACT = Set.of("Connection", "Statement", "PreparedStatement", "CallableStatement", "ResultSet", "Scanner", "Formatter", "Socket", "ServerSocket", "ZipFile", "JarFile", "RandomAccessFile", "FileChannel", "SocketChannel", "ServerSocketChannel", "Workbook", "XSSFWorkbook", "HSSFWorkbook", "SXSSFWorkbook", "SqlSession")` · `SUFFIXES = List.of("InputStream", "OutputStream", "Reader", "Writer")` · `MEMORY = Set.of("StringWriter", "StringReader", "CharArrayReader", "CharArrayWriter", "ByteArrayInputStream", "ByteArrayOutputStream")` · `JDBC = Set.of("Connection", "Statement", "PreparedStatement", "CallableStatement", "ResultSet")` · `KNOWN_PACKAGES = List.of("java.sql", "javax.sql", "java.io", "java.nio.channels", "java.util", "java.util.zip", "java.util.jar", "java.net", "org.apache.poi", "org.apache.ibatis")` · `CLOSERS = Set.of("close", "closeQuietly", "closeSilently", "closeStream", "closeConnection", "closeStatement", "closeResultSet", "closeAll", "release", "dispose", "shutdown", "free")` · `TRANSFER = Set.of("add", "put", "offer", "push", "set", "register")` · `SERVLET_OWNERS = Set.of("request", "response", "req", "resp")`.
5. **자원 형식 `isResource(String simple, CompilationUnit cu)`** — `MEMORY` 면 false. `EXACT` 에 들거나 `SUFFIXES` 중 하나로 끝나면 후보. 후보라도 cu 의 **단일 형식 import** 가운데 마지막 이름이 simple 과 같은 것이 있고 그 패키지가 `KNOWN_PACKAGES` 로 시작하지 않으면 false(JavaParser `Statement`·Hibernate 등 이름 충돌). import 가 없거나 `*` 면 true. 형식 글은 `simpleType`(제네릭·`[]`·패키지 뗌 — `ValueAst` 와 같은 규칙, 배열이면 false). `var` 는 초기화식이 `ObjectCreationExpr` 일 때 그 형식 이름, 아니면 false.
6. **만든 자리 `creation(Expression)`** — `strip` 뒤 `ObjectCreationExpr`(익명 몸 없음) 또는 `MethodCallExpr`. 그 밖(이름·필드·형 변환·배열·조건식·null·리터럴)은 소유가 아니라 후보 아님. 예외 — 래퍼 `new W(a, …)` 의 첫 인자 a 가 `MEMORY` 형식의 이름(`declaredType`)이거나 `new <MEMORY>(…)` 이거나 `System.in/out/err`(FieldAccessExpr scope `System`)면 **메모리 래퍼라 후보 아님**; 첫 인자가 메서드 매개변수·필드·`this.x`·`FieldAccessExpr` 인 이름이면 **호출자 소유를 감싼 래퍼라 후보 아님**(commons-io `CopyUtils`). `MethodCallExpr` 가 `getOutputStream`·`getWriter`·`getInputStream`·`getReader` 이고 scope 가 이름이며 그 `declaredType` 이 `ServletRequest`·`ServletResponse` 로 끝나거나(`HttpServletResponse`) 이름이 `SERVLET_OWNERS` 에 들면 **컨테이너 소유라 후보 아님**.
7. **후보 `candidates(cu)`** — `cu.findAll(VariableDeclarator.class)` 중 부모가 `VariableDeclarationExpr` 이고 그 부모가 `ExpressionStmt`(= 지역 변수, try 자원·for 머리·필드 제외)인 v. 형식이 `isResource`. 초기화식이 `creation` 이면 init = 그 식; 초기화식이 `NullLiteralExpr`(또는 없음)이면 같은 메서드 몸(`enclosingBody(v)` — 가장 가까운 `CallableDeclaration`·`InitializerDeclaration`·`LambdaExpr` 의 몸)에서 **첫 `AssignExpr`**(target 이 그 이름의 `NameExpr`, 연산자 ASSIGN)의 value 가 `creation` 이면 init = 그 value 와 그 `AssignExpr`; 아니면 후보 아님. 같은 메서드 몸이 없으면(필드 초기화 블록 밖) 후보 아님.
8. **해제·넘김 `released(v, body)`** — 몸 안 노드를 훑어 하나라도 참이면 해제: (ⅰ) `MethodCallExpr` 이름 ∈ `CLOSERS` 또는 `close` 로 시작, scope 가 그 이름(`x.close()`) **이고 그 호출의 조상에 `TryStmt` 의 `finallyBlock` 이 있다** (ⅱ) `MethodCallExpr` 이름 ∈ `CLOSERS` 또는 `close` 로 시작하고 인자에 그 이름이 있다(`IOUtils.closeQuietly(x)` — finally 안이 아니어도) (ⅲ) `ReturnStmt` 의 식 안에 그 이름이 있다(`return x` · `return new Y(x)` · `return wrap(x)`) (ⅳ) `AssignExpr` 의 value 가 그 이름이고 target 이 `FieldAccessExpr`·`this.x` 또는 몸 안에 선언 없는 `NameExpr`(필드) (ⅴ) 그 이름이 `ObjectCreationExpr` 의 인자인데 그 형식이 `isResource`(래퍼에 넘김 — 래퍼 변수가 따로 후보다) (ⅵ) 그 이름이 `MethodCallExpr` 의 인자이고 메서드 이름이 `TRANSFER` 에 들거나 `add`·`put`·`set`·`register` 로 시작한다 (ⅶ) 그 이름이 `LambdaExpr` 몸 또는 익명 클래스 몸(`ObjectCreationExpr.getAnonymousClassBody`) 안에 나온다 (ⅷ) v 가 try-with-resources 자원이다(후보 단계에서 이미 제외). `x.close()` 가 **finally 밖에만** 있으면 해제 아님 — 예외 경로 누수(KISA 5-2 의 뜻)라 지적한다.
9. **resourceLeak** — 후보 v 가 `released` 아니면 `Hit(RESOURCE_LEAK, v)`(선언 줄). 같은 선언자는 한 건.
10. **tryWithResources — 판정 = 고침 전제** — `cu.findAll(TryStmt.class)` 중 `getResources()` 비고 `getFinallyBlock()` 있는 t. finally 몸을 **close 문장 목록**으로 읽는다: 문장마다 ⓐ `n.close();` ⓑ `if (n != null) n.close();`(블록 유무 불문, else 없음) ⓒ `try { n.close(); } catch (…) { … }`(catch 몸은 불문 — 로그·printStackTrace·빈 것) ⓓ `Util.closeQuietly(n);`·`closeQuietly(n);`(인자 하나가 이름) — 다른 문장이 하나라도 있으면 판정 없음. 이름 집합 N(1 ≤ |N| ≤ 3, 중복 없음). 이름마다: ⓔ t 와 **같은 블록**(`t.getParentNode()` 가 `BlockStmt`)에서 t 보다 앞 문장에 지역 선언 `T n = null;`(**꼴 B**) 또는 `T n = <creation>;`(**꼴 A** — 이때 선언은 t **바로 앞** 연속 문장이어야 한다, 사이에 다른 문장 없음) · T 가 `isResource`(`var` 아님) ⓕ 꼴 B 면 t 의 try 블록 **첫 |N| 문장** 안에 `n = <creation>;`(ExpressionStmt·AssignExpr·ASSIGN) 이 있다(순서 불문, 전부 있어야) ⓖ n 이 try 블록의 대입 문장 밖·catch 블록·finally 의 close 밖·t 뒤 형제 문장 어디에도 `NameExpr` 로 안 나온다(try 몸 안 사용은 당연히 허용 — twr 범위) ⓗ close 예외: T ∈ `JDBC` 면 `SQLException`, T 가 `SUFFIXES`·`ZipFile`·`JarFile`·`RandomAccessFile`·`*Channel`·`Socket`·`ServerSocket`·`Workbook*` 면 `IOException`, 그 밖(`Scanner`·`Formatter`·`SqlSession`)은 없음. 필요한 예외가 있으면 t 의 catch 매개변수 형식(union 포함) 마지막 이름 가운데 `Exception`·`Throwable`·그 예외가 있거나, 둘러싼 `CallableDeclaration` 의 `throws` 에 그 셋 중 하나가 있어야 한다 ⓘ 대입 문장을 뺀 try 블록이 비지 않는다. 전부 맞으면 `Hit(TRY_WITH_RESOURCES, t)`(try 줄). 이름마다 틀리면 그 try 는 지적 없음(부분 변환 없음).
11. `apply(cu, on)` 꼴은 `ValueAst.apply` 와 같다(켜진 규칙만 · 줄·규칙 정렬 · `Range` 중복 제거). 메서드 열다섯 안팎(`apply`·`candidates`·`isResource`·`imported`·`creation`·`memoryWrapper`·`servletOwned`·`enclosingBody`·`firstAssign`·`released`·`inFinally`·`tryWithResources`·`closeStatements`·`closeName`·`declaredBefore`·`usedOutside`·`closeException`·`covered`·`simpleType`·`strip`·`same`·`line`). `declaredType` 은 `ValueAst` 의 것을 package-private 로 열어 쓴다(복사 금지 — `ValueAst.declaredType` 접근자를 `static String declaredType(Expression)` 으로 바꾸는 것만, 몸 불변).

### ValueAst(5-60c) — equalsLiteralFirst + isFloat
12. 상수 `EQUALS_FIRST = "java.equalsLiteralFirst"` · `EQUALS_NAMES = Set.of("equals", "equalsIgnoreCase")`. **equalsLiteralFirst** — `cu.findAll(MethodCallExpr.class)` 중 이름 ∈ `EQUALS_NAMES`, 인자 하나가 `strip` 뒤 `StringLiteralExpr`, scope 가 있고 `strip` 뒤 `StringLiteralExpr`·`SuperExpr`·`ClassExpr` 이 아닌 것 → `Hit(EQUALS_FIRST, m)`. scope 없음(`equals("x")` = this)·상수 인자(`x.equals(CONST)`)·`Objects.equals` 는 지적 없음.
13. `static boolean isFloat(ObjectCreationExpr o)` — 첫 인자(`strip`·부호 벗김)가 `DoubleLiteralExpr` 로 값 글이 `f`/`F` 로 끝남 · `CastExpr` 형식 `float`/`Float` · 이름의 `declaredType` ∈ {`float`, `Float`} · `MethodCallExpr` 이름 ∈ {`floatValue`, `parseFloat`, `nextFloat`}. `ValueFix` 가 라-5 건너뜀 판정에 쓴다. `bigDecimals` 판정은 불변.

### TxAst(5-59d) — 시험 클래스 제외
14. `TEST_MARKERS = Set.of("Test", "RunWith", "ExtendWith", "SpringBootTest", "ContextConfiguration", "SpringJUnitConfig", "WebAppConfiguration", "TestExecutionListeners", "Rollback", "TransactionConfiguration", "DataJpaTest", "WebMvcTest")`. 클래스(`ClassOrInterfaceDeclaration`)의 애너테이션 또는 그 메서드 어느 하나의 애너테이션 마지막 이름이 `TEST_MARKERS` 에 들면 그 클래스의 `txRollbackFor` 판정을 전부 건너뛴다(txSelfCall·txPrivate 는 그대로 — 시험이라도 프록시 결함은 결함). 경로(`src/test`)는 안 본다 — `TxAst.apply` 에 경로가 없고 `taint` 에 분기를 못 더한다. eGov `EgovTestAbstractSpring`(`@ExtendWith(SpringExtension.class)`) 셋이 사라진다.

### Cleanup(5-60b·5-60d) — 단계 둘
15. `RULES`(14, 순서 고정) = 기존 아홉 + `java.refEquals`, `java.weekYear`, `java.equalsLiteralFirst`, `java.bigDecimalDouble`, `java.tryWithResources`. `DEFAULT`(A, 12) = `RULES` − `OPTIONAL` · `OPTIONAL`(B) = `List.of("java.bigDecimalDouble", "java.tryWithResources")`. `VALUE_RULES = Set.of(refEquals, weekYear, equalsLiteralFirst, bigDecimalDouble)` · `VALUE = "value"` · `RESOURCE = "resource"`. 5-60b 에서 `RULES` 를 열넷으로 한 번에 적는다(없는 id 는 `on` 필터가 거르고 `/api/cleanup/rules` 는 def 없는 id 를 건너뛴다 — 라우트·스모크 수는 5-60b 12 → 5-60c 13 → 5-60d 14).
16. **단계와 차례** — `① delete → ② marker → ③ value → ④ resource → ⑤ order → ⑥ eol`. value 는 줄 수를 안 바꾸고, resource 는 줄을 지우니 order(줄 슬롯) 앞에 둔다. 단계마다 직전 결과를 다시 검사한 `st.cur` 로 대상 줄을 읽는다(기존과 같다).
17. **`editStage` 일반화** — `markerStage` 를 지우고 `private void editStage(State st, String stage, Set<String> ids, Editor fn)` — `targets` 비면 return · `Edits e` · `List<Skip> local` · `fn.edit(st, targets, e, local)` · `commit(...)`. `interface Editor { void edit(State st, Set<String> targets, Edits e, List<Skip> local); }`(Cleanup 안 중첩, package-private). `clean` 은 `editStage(st, MARKER, Set.of(Ignores.UNUSED), (s, t, e, l) -> removeMarkers(s.source(), lines(s.cur, t), enabledIds, e, l))` · `editStage(st, VALUE, VALUE_RULES, (s, t, e, l) -> ValueFix.apply(s.text, s.cur, t, parser, e, l))` · `editStage(st, RESOURCE, Set.of(ResourceAst.TRY_WITH_RESOURCES), (s, t, e, l) -> ResourceFix.apply(s.text, s.cur, parser, e, l))`. 람다에 분기 없음(unsafe 판정은 수정기 안). 클래스 메서드 29 그대로.

### ResourceFix(5-60d) — try-with-resources
25. `static void apply(String text, List<Finding> cur, JavaSource parser, Cleanup.Edits e, List<Cleanup.Skip> skips)` — unsafe·파싱 판정은 §3-21 과 같다. `ResourceAst.apply(cu, Set.of(TRY_WITH_RESOURCES))` 의 Hit(= TryStmt t)마다 **글 꼴**을 확인한다(판정은 AST 가 끝냈으니 여기는 줄 꼴만): ⓐ `try {` 줄이 `^\s*try\s*\{\s*$` ⓑ 이름마다 선언 줄이 `^\s*(final\s+)?<T …>\s+n\s*=\s*(null|<init>)\s*;\s*$` 한 문장뿐(꼴 B 의 선언·꼴 A 의 선언) ⓒ 꼴 B 의 대입 줄 `^\s*n\s*=\s*<init>\s*;\s*$` 가 한 줄(init 이 여러 줄이면 ✗) ⓓ `} finally {` 줄이 `^\s*\}\s*finally\s*\{\s*$` ⓔ finally 의 닫는 줄이 `^\s*\}\s*$` 이고 finally 몸은 그 사이 줄 전부(= close 문장들). 하나라도 틀리면 `Skip(RESOURCE, "줄 n: 줄 꼴이 달라 못 고침(한 줄에 다른 코드·여러 줄 식)")`.
26. 변환(한 try 에 대해 `Edits`): 선언 줄 삭제 · 꼴 B 대입 줄 삭제 · `try {` 줄 → 같은 들여쓰기 + `try (T1 n1 = init1; T2 n2 = init2) {`(순서 = 꼴 B 는 대입 순서, 꼴 A 는 선언 순서; `final` 뗌; init 글은 원문 그대로) · `} finally {` 줄 → 같은 들여쓰기 + `}` · finally 몸 줄 전부와 닫는 줄 삭제. 한 파일에 try 가 여럿이면 전부(줄이 서로 안 겹친다 — 겹치면(중첩 try 둘 다 Hit) 바깥 것만, 안쪽은 「겹친 try」 사유).
27. 되돌림은 `commit` 이 한다 — 대상 `java.tryWithResources` 가 줄어야 하고, 지운 줄 위 지적은 사라져도 된다(§3-18). 바뀐 try 줄로 옮겨 간 지적(`security.pathTraversal` 등 init 식에 걸린 것)은 touched 규칙 이름 수가 같아 채택된다.
